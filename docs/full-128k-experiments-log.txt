--------------------------------------------------------------------------------
WHAT WENT WRONG (root causes)
--------------------------------------------------------------------------------
1. OFFLOAD OOM (4626)
   CPU activation offload keeps the full activations on-GPU and streams them to
   host RAM asynchronously. At 128k the stream can't drain fast enough, so
   activations pile up and the peak stays high -> OOM in the MoE grouped-GEMM.
   Lesson: offload is the wrong tool at very long context.

2. FRAGMENTATION OOMs (4629, 4630)
   EP32/CP1 sits at a ~167 GB floor per rank: base ~50 GB + ~117 GB of recompute
   checkpoints (78 layer inputs at 128k). That leaves <6 GB headroom. When the
   LONGEST 128k sample lands on an already-fragmented rank, the ~8 GB LoRA-expert
   allocation fails. It is STOCHASTIC: 4629 died at step 12, 4630 at step 8,
   because sample-to-rank assignment reshuffles every epoch. Pure allocator tuning
   (garbage_collection_threshold) did NOT create real headroom -> need to lower the
   actual peak, not defragment.

--------------------------------------------------------------------------------
WHAT WE LEARNED
--------------------------------------------------------------------------------
* Full 744B @ 128k IS runnable on 4 nodes -- public stack, finite loss (4627, rc=0).
  The core goal is proven.
* RECOMPUTE > OFFLOAD for long context -- the single most important fit lever.
* EP32/CP1 FITS BUT IS MARGINAL: great for a short proof, too thin (<6 GB headroom)
  for a sustained multi-step run.
* The RECOMPUTE CHECKPOINTS (~117 GB) DOMINATE memory, not the base. This flips the
  grid choice: CP2 halves the dominant term, so CP2/EP16 (base 99 but checkpoints
  ~58) has a LOWER peak (~161 GB) than EP32/CP1 (~175 GB) despite the bigger base.
  -> CP2/EP16 (4631) is the robust grid, and it's what the 30-layer runs used.
* The robust long-term headroom + throughput lever is FP8-BASE (base 50->25 GB),
  which would also let us DROP recompute. It is built but OFF by default
  (GLM_FP8_BASE=1; Task-1 wrap in overlays/megatron-bridge/gpt_provider.py); the
  load/carve-out plumbing (Task 2/4) is unfinished.

--------------------------------------------------------------------------------
THE FOUR TECHNIQUES THAT MAKE 128k WORK AT ALL  (see how-128k-744b-works-EXPLAINED.txt)
--------------------------------------------------------------------------------
1. EP32 (or EP16+CP2) to shard the 744B base.
2. Full activation recompute (NOT offload) to absorb 128k activations.
3. Chunked DSA indexer (DSA_INDEXER_Q_CHUNK=4096) to kill the O(S^2) ~206 GB
   attention-score matrix.
4. Base-scale fix: dequantize the FP8 checkpoint's 128x128 blockwise scale on load
   (else base loads ~6000x too large -> NaN).

--------------------------------------------------------------------------------
* EP32/CP1 (4627): ~1,130-1,160 tok/s = ~68-70k tok/min, ~13.5 min/step, ~40 TFLOPS/GPU.

* CP2/EP16 expected higher (30-layer CP2 runs reached ~215k tok/min) -- to be
  confirmed on 4631.
